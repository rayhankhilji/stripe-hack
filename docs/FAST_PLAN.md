## 0. The product in one paragraph
Ghost is an agent-first revenue operator.
1. It ingests Sapora Networks' records from Era (recorded fixtures in `fixtures/era/**`, or live).
2. It resolves customers across 7 systems.
3. It runs a **deterministic** detector for "closed-won, never billed" revenue and checks eligibility rules R-01..R-10.
4. An agent (Mastra + OpenAI) explains the case with citations to source records.
5. A human approves, and Ghost creates a **real Stripe test-mode invoice**. The operator pays it on Stripe's hosted page with card 4242.
6. The **verified webhook** `invoice.paid` marks the case `recovered` and suppresses collection reminders.
7. Everything is written to `audit_event`, and the UI streams that audit feed as the agent's live activity.

**Hero demo case (real data):** Tidewater Capital `acct-6`.
- `deal-127` $51,500 (lines `oli-deal-127-0` $16,400 + `oli-deal-127-1` $35,100), `deal-23` $11,000 and `deal-24` $9,700, all Closed Won.
- Orders `order-127`, `order-23` and `order-24` are all `Draft`.
- `contract-4` reads "Business plan for Tidewater Capital: 20 seats at 9,700 per year." and has status "In Approval Process".
- **Total $72,200.** Gate: R-10 warns because the contract is not activated, so human approval is required.

## 4. Eligibility rules (B3 implements, exact names)
| Rule | Name | pass | warn | fail |
|---|---|---|---|---|
| R-01 | Customer identity corroborated | resolved in ≥2 systems | 1 system | — |
| R-02 | Revenue is contractually committed | all lines from Closed Won deals | — | otherwise |
| R-03 | Line items reconcile to deal amount | Σ lines == deal amount for every deal | — | mismatch |
| R-04 | No activated order exists | no `Activated` order for these deals | — | otherwise |
| R-05 | Not already invoiced | no deal in invoicedDealExternalIds | — | otherwise |
| R-06 | No dispute on record | signals.dispute == 0 | — | >0 → **escalated** |
| R-07 | Customer is active | status active | — | churned |
| R-08 | Service delivery evidenced | signals.usage ≥ 1 | 0 | — |
| R-09 | Within invoice policy cap | amount ≤ INVOICE_AMOUNT_CAP_CENTS | — | above |
| R-10 | Contract activated | a contract is `Activated` | `In Approval Process`/`Draft` or none ("human approval required") | `Expired` |

`decide`: any R-06 fail → `escalated`; any other fail → `needs_review`; else `ready_for_approval` (AUTO_INVOICE_ENABLED=false, so a human always approves). The reason lists the failing or warning rule names.

## 5. Evidence role mapping (deterministic; B5 detect.ts)
| Source | Role | Quote |
|---|---|---|
| salesforce Opportunity | commitment | `"<Name>" — <StageName>, $<Amount>, closed <CloseDate>` |
| salesforce OpportunityLineItem | commitment | `Description` + ` $<TotalPrice>` |
| salesforce Contract | contract_term | `Description` + " " + `SpecialTerms` + " Status: " + Status |
| salesforce Order | billing_state | `Order <OrderNumber> status <Status>, effective <EffectiveDate>, $<TotalAmount>` |
| aws fact_payments, zendesk ticket, gong call | usage_signal | ticket subject / call title / `payment <event_id> <amount> <status>` |
| drive file whose name contains "Dispute" | dispute_signal | first 240 chars of content |
| slack message, other drive docs | context | the message text (first 240 chars) |

Each quote must appear verbatim in `source_record.body_text`, which is how `verified=true` is set. `body_text` is built by ingest from the same fields in the same format.

## 6. State machines
- **Finding:**
  - Main path: `detected → analyzing → ready_for_approval → approved → invoiced → recovered`.
  - From `analyzing` the case can also go to `needs_review` or `escalated`. From `ready_for_approval` it can also go to `rejected`.
  - Any non-terminal state can go to `failed`.
  - Re-analysis is allowed from `needs_review`, `ready_for_approval`, `failed` and `detected`.
- **Invoice (from Stripe):** `invoice.finalized` → open. **`invoice.paid` → paid**, which marks the finding `recovered`, suppresses reminders and writes audit `outcome_verified`. `invoice.payment_failed` sets `lastPaymentError` and adds a needs-attention item. `invoice.voided` → void. `invoice.marked_uncollectible` → uncollectible. Other events → ignored.
- **Reminders:** `scheduled → drafted (outbox) → sent_simulated`. Any open reminder → `suppressed` when the invoice is paid.

## 7. Expansion signals (B6, deterministic)
A customer is a candidate when **all** of these hold:
- status is active,
- 0 open (not closed) deals,
- ≥ 10 feature-request Salesforce Cases (Type contains "Feature"),
- ≥ 1 Gong call titled "Expansion scoping" or "Commercial review", or whose transcript mentions "next tier"/"usage is up".

Signal score = min(100, 4×featureRequests + 20×gongSignals). Evidence comes from those records. This is expected to surface Vernall Capital `acct-8`.
